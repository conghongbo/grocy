## Common foundation findings

### F01 — URL ownership and deployment are undefined (P0)

S: [client.ts:1–7](/Users/alaricvoss/Documents/UWCCOMPX574/grocy/frontend/src/api/client.ts:1) concatenates a fixed `/api` with an arbitrary string. Examples of that expression, not executed requests:

| Caller argument | Result | Meaning |
| --- | --- | --- |
| `/system/info` | `/api/system/info` | Correct registered path for a root deployment on the serving origin |
| `system/info` | `/apisystem/info` | Wrong join |
| `/api/system/info` | `/api/api/system/info` | Duplicates the prefix used in the earlier catalogue |

The backend supports a configured base path in [app.php](/Users/alaricvoss/Documents/UWCCOMPX574/grocy/app.php:102). Root-relative `/api` does not preserve a deployment prefix such as `/grocy`. A separately served Vite page sends it to the Vite origin; there is no checked-in proxy to PHP. Vite's proxy is an explicit server configuration facility ([official documentation](https://vite.dev/config/server-options#server-proxy)).

Recommendation: one foundation-owned API base and path builder; define adapter paths as suffixes such as `/tasks`, while documentation continues to show full registered paths. Encode path segments and repeated query parameters. Specify production asset base and router base independently from API base. Preserve PHP login, initialization, API, file and image routes; an SPA fallback must not return HTML for these requests. No particular router package or API URL has yet been selected.

### F02 — Authentication is not integrated; same-origin cookies are not inherently broken (P0)

S: the helper forwards `RequestInit` and sets no credentials/header policy. Under default authentication, [DefaultAuthMiddleware](/Users/alaricvoss/Documents/UWCCOMPX574/grocy/middleware/DefaultAuthMiddleware.php:11) tries an API key then a session. [app.php](/Users/alaricvoss/Documents/UWCCOMPX574/grocy/app.php:94) names the header `GROCY-API-KEY`; [ApiKeyAuthMiddleware](/Users/alaricvoss/Documents/UWCCOMPX574/grocy/middleware/ApiKeyAuthMiddleware.php:32) also supports the query alternative and restricted iCal secrets. There is no registered `/api/login`, OAuth bearer-token or token-refresh workflow in this source.

I: ordinary Fetch sends same-origin credentials by default; omitting `credentials: "include"` does **not** prevent a same-origin session from working. A separate-origin cookie design needs both a credentials policy and compatible server CORS responses. Current [CorsMiddleware](/Users/alaricvoss/Documents/UWCCOMPX574/grocy/middleware/CorsMiddleware.php:13) uses wildcard origin and supplies no Allow-Credentials header. These browser requirements are described in [MDN's Fetch documentation](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch).

Recommendation: retain the existing [login/logout flow](/Users/alaricvoss/Documents/UWCCOMPX574/grocy/controllers/LoginController.php:16) initially and use a common browser origin, including a configured development proxy if needed. Verify login, logout, redirect/cookie paths and expired sessions together. Do not ship an administrator API key as frontend configuration. Support another configured authentication class only after inspecting that deployment.

R: [AuthMiddleware](/Users/alaricvoss/Documents/UWCCOMPX574/grocy/middleware/AuthMiddleware.php:18) classifies API paths using the literal prefix `/api/`, returns an empty 401 for that case, and otherwise redirects to login. Check subdirectory routing, redirects, unauthenticated OPTIONS, and actual cookie behavior. Authentication bypass in demo/dev/embedded modes cannot establish restricted-user acceptance.

### F03 — Successful empty and non-JSON responses cannot use this decoder (P0)

S: [client.ts:15](/Users/alaricvoss/Documents/UWCCOMPX574/grocy/frontend/src/api/client.ts:15) always calls `response.json()`. [EmptyApiResponse](/Users/alaricvoss/Documents/UWCCOMPX574/grocy/controllers/Api/BaseApiController.php:29) returns 204; generic edit/delete, task completion/undo, settings writes and file uploads use it. [file serving](/Users/alaricvoss/Documents/UWCCOMPX574/grocy/controllers/Api/FilesApiController.php:64) returns a binary stream with MIME type; [iCal](/Users/alaricvoss/Documents/UWCCOMPX574/grocy/controllers/Api/CalendarApiController.php:92) returns calendar text.

I: those successful responses cannot be decoded as JSON. Giving the helper a TypeScript `void` type does not change its runtime parsing. Recommendation: explicit JSON, empty, text and binary response modes plus raw binary upload; check expected response media type and retain a bounded text fallback for unexpected HTML. Keep endpoint success formats, including generic create's 200 response, unchanged.

### F04 — Request construction needs an explicit contract (P0)

S: `RequestInit` allows callers to supply body, headers and cancellation, but the helper provides no JSON serialization or query builder. [GetParsedAndFilteredRequestBody](/Users/alaricvoss/Documents/UWCCOMPX574/grocy/controllers/Api/BaseApiController.php:158) requires exactly `Content-Type: application/json`; it preserves arrays/booleans and sanitizes other values. An ordinary object is not a ready-made Fetch body.

Recommendation: adapters supply column/action DTOs; transport serializes JSON and sets the exact header. Keep raw file upload separate: [UploadFile](/Users/alaricvoss/Documents/UWCCOMPX574/grocy/controllers/Api/FilesApiController.php:82) reads the request stream and does not expect a multipart form or JSON wrapper. Filenames use the source-defined Base64 convention plus URL-safe transport of the path segment, not an invented filename API.

The query helper must append repeated `query[]` values and `order`, `limit`, `offset` only for endpoints using [QueryData](/Users/alaricvoss/Documents/UWCCOMPX574/grocy/controllers/Api/BaseApiController.php:49). There is no standard total-count envelope. [CurrentStock](/Users/alaricvoss/Documents/UWCCOMPX574/grocy/controllers/Api/StockApiController.php:353) does not apply that helper. Port page-only query options separately rather than assuming every HTML query works on its API counterpart.

### F05 — Error information and failure categories are lost (P0)

S: [client.ts:9](/Users/alaricvoss/Documents/UWCCOMPX574/grocy/frontend/src/api/client.ts:9) throws only a status-containing string. Backend errors include `error_message`, optional `error_details`, empty authentication responses, and different statuses depending on handler/catch placement ([base response helpers](/Users/alaricvoss/Documents/UWCCOMPX574/grocy/controllers/Api/BaseApiController.php:34), [global exception handler](/Users/alaricvoss/Documents/UWCCOMPX574/grocy/controllers/ExceptionController.php:34)).

Recommendation: a structured transport error retains numeric status, readable backend message, endpoint, optional diagnostic details and a safe fallback when JSON is absent. Distinguish HTTP failures, network errors, cancellation and decode failures. Modules interpret validation/business errors; the shell handles session expiry. Do not display stack traces as ordinary UI messages or convert every 400 into a field-validation error.

For example, task completion checks permission outside its catch ([TasksApiController](/Users/alaricvoss/Documents/UWCCOMPX574/grocy/controllers/Api/TasksApiController.php:17)); chore execution checks inside ([ChoresApiController](/Users/alaricvoss/Documents/UWCCOMPX574/grocy/controllers/Api/ChoresApiController.php:64)). Thus a permission failure can be 403 or 400. Generic missing-object GET returns 404; edit/delete return 400. These are source-derived expectations awaiting HTTP verification, not inconsistencies to hide in React.

### F06 — Generic typing does not establish wire types (P0)

S: no DTO, parser, normalization or domain adapter exists. [CurrentUser](/Users/alaricvoss/Documents/UWCCOMPX574/grocy/controllers/Api/UsersApiController.php:144) returns a filtered LessQL collection, not an explicitly selected single user. [GetCurrent tasks](/Users/alaricvoss/Documents/UWCCOMPX574/grocy/services/TasksService.php:9) adds nested category/assignee data that generic task rows do not contain. Generic single/list records also differ in absent/null `userfields` ([GenericEntityApiController](/Users/alaricvoss/Documents/UWCCOMPX574/grocy/controllers/Api/GenericEntityApiController.php:194)).

Recommendation: separate wire DTOs, validated UI models, and write payloads. Treat the schema dictionary as source-derived guidance; SQL affinity and OpenAPI declarations are not captured JSON scalar types. Verify numeric IDs/amounts, 0/1 flags, null/empty text, missing nested data and empty collections. Normalize known fields deliberately; blanket Boolean conversion makes a string `"0"` true, and blanket number conversion corrupts identifiers such as barcodes.

Preserve date-only strings and serialize action timestamps using the source's `YYYY-MM-DD HH:mm:ss` format ([IsIsoDateTime](/Users/alaricvoss/Documents/UWCCOMPX574/grocy/helpers/extensions.php:132)). Some invalid timestamp inputs fall back to server “now”. The PDO configuration also applies empty-string-to-null handling ([DatabaseService](/Users/alaricvoss/Documents/UWCCOMPX574/grocy/services/DatabaseService.php:90)); capture complete request-to-response behavior before declaring null and empty string equivalent.

### F07 — Shell/bootstrap and command boundaries are missing (P0 design, staged implementation)

S: the frontend has no permission, settings, translation, navigation or data-refresh layer. [BaseController](/Users/alaricvoss/Documents/UWCCOMPX574/grocy/controllers/BaseController.php:25) and [layout](/Users/alaricvoss/Documents/UWCCOMPX574/grocy/views/layout/default.blade.php:122) inject information not supplied by `GET /api/user`. User permission administration requires ADMIN; it is not a normal-user effective-permissions bootstrap endpoint ([UsersApiController](/Users/alaricvoss/Documents/UWCCOMPX574/grocy/controllers/Api/UsersApiController.php:156)).

Recommendation: define a bootstrap model for base URLs, current user, effective permissions, feature flags, settings, locale/timezone, plural/unit translations and precision. Prefer a small server-provided bootstrap through a retained Blade host during incremental migration. A standalone JSON bootstrap/read adapter is proposed backend-facing work, not a route that currently exists. Existing system/settings endpoints can supply part of the model; do not treat `/system/config` as a ready-made, minimal bootstrap DTO.

Keep reads separate from commands even when HTTP uses GET: label printing, barcode lookup with add enabled, and iCal chore actions have side effects ([StockApiController](/Users/alaricvoss/Documents/UWCCOMPX574/grocy/controllers/Api/StockApiController.php:437), [printing](/Users/alaricvoss/Documents/UWCCOMPX574/grocy/controllers/Api/StockApiController.php:670), [CalendarApiController](/Users/alaricvoss/Documents/UWCCOMPX574/grocy/controllers/Api/CalendarApiController.php:126)). Future query caches must not prefetch or automatically retry them. Retain [StrictMode](/Users/alaricvoss/Documents/UWCCOMPX574/grocy/frontend/src/main.tsx:7); React documents extra development effect checks ([official reference](https://react.dev/reference/react/StrictMode)). Submit commands from explicit actions, not mount effects. No existing cache/retry/effect implementation is being blamed here.

## Integration recommendation

Keep the build scaffold, mount entry point, lockfile, API-directory boundary, existing backend and legacy UI as the comparison implementation. Refactor the shared transport, define hosting/auth/bootstrap, and establish DTO/error conventions before delegating module adapters. A new backend business API is not required merely because React replaces jQuery.

Implement a small system/current-user read and then Tasks as the first complete vertical slice. Tasks exercises generic CRUD, named commands, empty responses, permissions, selectors, settings and custom fields with fewer dependencies than stock. Batteries can then validate local extensions; Chores adds scheduling and stock side effects. Build shared master data and stock next, followed by shopping, recipes and meal planning. Implement file support before dependent pictures/manuals; plan calendar/report bridges early even if their screens arrive later. Administration and extension parity must close before full cutover.

Use per-page coexistence to keep unmigrated behavior available. A standalone SPA is possible only after every required template input has an API/read adapter or an explicitly designed replacement. The [integration checklist](/Users/alaricvoss/Documents/UWCCOMPX574/grocy/docs/frontend-integration-checklist.md) makes those dependencies and runtime acceptance gates concrete.
